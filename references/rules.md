# 铁律 0–10(科研:严谨、诚实)

科研项目。数据造假/误记是致命错误。铁律 0–10 是硬约束,写代码、报数字、下结论前逐条自检。
**全文即规则,不依赖记忆回忆。** teacher 与 student 共同受约束。

## 铁律 0:分析现象前,先确认它真实且新
先确认:(a) 现象在原版/baseline 里真实存在吗?(b) 文献报道过吗?
不是新现象 → 后续全是沉没成本。不许草草了事。

## 铁律 1:有参考源码,逐行读再写自己的
实现已发表方法前逐行对照源码,确认每个关键变量,不照抄、不臆测。

## 铁律 2:每个修改单独验证后再组合
一次只开一个改动,跑短训练看目标指标趋势;绝不在两个未验证改动同时存在时跑长训练。

## 铁律 3:永远先跑原版 baseline 作对照 —— 且先查项目内已有
"这现象原版有吗?"是发现崩塌后第一个问题,不是最后一个。原版不崩你的改崩了 = 你的 bug。

**【硬前置·项目内已有检索】(2026-08-05 补,防重复造轮子/脏实验重演)**
任何**新实验启动前**或**新脚本编写前**,必须先查项目内已有产物,有则分析/复用、不重复:
- 实验前:`grep/read EXPERIMENT_LOG.md / DONE_LOG.md` + 历史 eval json,确认"此问题是否已有**干净数据**(单变量对照)回答"。有 → 先分析已有,**禁止重复跑脏实验**。
- 脚本前:`ls scripts/ && grep -rl <功能>` 确认"是否已有实现"。有 → 复用,**禁止重写**。
- 这是铁律1(对照源码)的**项目内延伸**:不只对照外部参考,还要对照项目已有产物。
- 教训溯源:pi 曾①重写已存在的 endpoint_error_probe.py ②跑 C1/C3 脏对比却忽略项目已有的干净 γ 族(EXPERIMENT_LOG:679)——两次同模式失败。

## 铁律 4:监控你真正关心的指标
做 PRIMARY_METRIC 就监控 PRIMARY_METRIC,不是代理指标。代理指标会致盲。

## 铁律 5:报告保守,一次说准
用完整测试集不用子集;报均值±std+样本量;宁可低报再上调,不可高报再下调。

## 铁律 6:声称"新发现"前先查文献 30 分钟
先搜,别把已知问题当新发现。

## 铁律 7:沉没成本不是继续的理由
方向有问题(循环/已知/未验证)立即停,别因"已经投入了"而继续。

## 铁律 8:以严谨工程师视角审 claim —— 包括自己生成的 + 审证据链干净度
对任何 claim 确认:有没有用、有没有创新、有没有人做过。

**【扩展·审自己 + 证据链】(2026-08-05 补,防"叙事便利"用过期/脏数据)**
1. **审 claim 包括自己生成的 insight/narrative/hypothesis**,不只审别人的论文/导师的。对自己要和对别人一样狠(铁律8 对内)。
2. **生成 insight 后,显式列证据链**:每个支撑数据点 → 标注来源实验 → 标注是否**单变量干净对照**。
3. **多变量混淆的数据(如同时变 predictor+drift、温度+negatives)不可作为 insight 的决定性证据**,或必须降级标注"归因未净"。
4. **自问**:审稿人/导师挑这个 insight 的证据链,哪个数据点站不住?站不住的删/降级,**不许为了故事漂亮选择性用被自己否定过的数据**。
5. 教训溯源:pi 曾在 insight 文档里标了"C1vsC3 predictor 混淆不能归因",紧接着又把 C3 矛盾当"分布-样本张力实证"——自相矛盾,被 teacher 抓到。根因:叙事驱动 > 证据驱动。

## 铁律 9:不确定时不强下结论,理论可行就实验
双方都不确定、靠争论无法定论时别硬下结论。判理论是否自洽 → 自洽就做一个能**证伪**它的最小实验 → 用数据下判断。

## 铁律 10:引用先于断言,无源则弃权
写任何实验数字前:
1. 数字必须来自 `RESULTS_LEDGER.md`,或本轮内从磁盘文件(*.json/*.log/*.ckpt名)读出,行内标源。
2. **无来源 → 只写"未测/待实验",禁止写具体数字**,禁止"大概/应该是"填空。
3. 区分**实测**(有文件) vs **推断/预期**(显式标注,不混入 ledger)。
4. 下结论前从源文件重读关键数字确认,不凭记忆/口头估。
5. **可比性元数据(判据非枚举)**:任何 eval 数字,连同"**任何一改就会移动这个数的参数/先验**"一起记录——不是背一张固定清单(t_eps/N/split/seed/口径…),而是问"换了它,这个数还一样吗?会→必标"。**跨源对比前,先确认两边这些参数一致**;不一致→先对齐口径再比,否则差值可能是口径假象(血泪:先 split 后 t_eps/N 两次栽在这)。报差值用**配对检验/配对差±SE**(同测试集逐样本配对),不是各自的 std;区分 std(离散度)vs SE(均值精度),下显著性判断用 SE。

## 铁律 11:数据在确认你自己的假设时,是你最该自我批判的时刻
确认偏误在"数据支持我"时最强,这恰是加倍严审的信号,不是庆祝的信号。**双方(teacher 提的 idea、student 跑的结果)都受此约束**。
1. **归因前先查混淆**:声称"X 导致 Y"前,确认对比里**只有 X 变了**。一次改动多个变量(超参 + 语义 + 实现)就无法归因给任一个(接铁律2)。改动 commit 要逐行核对**实际改了几样**,别信 commit message 的"改了一样"。
2. **对自己的 idea 下手更狠**:验证的是**你自己**提的假设时,主动找"这是假象吗"的理由——混淆变量?口径不一致?指标测的是不是你以为的东西?(如 DNSMOS 测逐句 MOS ≠ 分布匹配)
3. **确认性证据要交叉验证**:一个"支持"的数字,换指标/换基线/换 split 还成立吗?尤其别用错基线(拿健康参考代理当对照)、别用饱和/不敏感的指标凑"持平"。
4. **措辞跟着证据收放**:证据只支持半句就只写半句("移植后更差"成立 ≠ "因为语义 X"成立)。发现自己上一轮措辞过头,**主动收回并更正**,不硬撑。
5. **庆祝在干净归因之后**,不在现象出现之时。临界数据没拿到前,结论是"候选",不是"坐实"。

## 铁律 12:novelty 门是持续闸门,claim 每次变形都要重过——不是"idea 出生时审一次"
消耗 GPU 前必过 novelty 门(teacher 用 novelty-reviewer,判定非 INCREMENTAL/KNOWN 才派活)。但门不是一次性的:
1. **触发重审的时刻**:idea 中途 **reframe / 换假说 / 换机制解释 / 换 claim** 时,即使原 idea 过过门,**变形后的新 claim 必须重过**。血泪:dual-space fork 从"drift 有用"→ reframe"分布-样本 trade-off"→"bug 即 feature"→"机制 paper",中途每次变形都没重审,直到跑完 6 次实验才发现全被 2512.10382 + warm-start/LoP 预占。
2. **深搜是硬要求,不是走过场**:novelty 判定必须基于**实际联网全文核实**(本地 PDF / fetch 全文 / 强搜索工具如 AnySearch 2000/天),不是只靠项目内 refs + 训练记忆。web_search snippet 是最弱证据,不足以判"新"。
3. **teacher 负责补做 `[需web复核]`**:novelty-reviewer 标的复核项,teacher 用强搜索工具(AnySearch/fetch PDF)实际查,查完才下 NOVEL 判定。查不到 ≠ 新,是没查够。
4. **claim 变形要在 IDEAS.md / REVIEW.md 留痕**:哪次变了、变成什么、重审判定,便于审计"这个新 claim 过门了吗"。

## 铁律 13:Run Identity Verification — 训练run的配置必须与声称的机制一致
在任何训练run的结果成为evidence前，必须验证run的**realized configuration**与声称的mechanism一致。
1. **检查项**:
   - hparams与脚本声称的一致（如声称"fid"则gamma>0且use_xpred=true）
   - TensorBoard loss分量与config implied的一致（如gamma>0且use_xpred，则必有train_loss_fid/drift/imf）
   - 若config有门控条件，检查条件满足（如gamma>0需use_xpred，否则分支不进→惰性配置）
2. **违反时**:视为misconfigured run，不得引用其数字。标注"INERT CONFIG"并重跑。
3. **机械执行**:写`verify_run_identity.py`脚本，入ledger前强制pass。不pass不入evidence。
4. **教训溯源**:vpred_fid run传gamma=1.0但漏use_xpred，导致fid分支从未执行（model.py:426条件`gamma>0 AND use_xpred`），run实为纯v-pred MeanFlow。因从未查TB loss分量，误当"v-pred+fid"引用23处，论文主线基于此搭建后作废。铁律11（数据顺心时加倍自审）人为失灵，asymmetric verification（forensic审可疑run、trust审自己设计的）导致confirmation bias单点失败。

## 铁律 14:把关机制必须 fail-closed,且必须有"能让它自己失败"的测试

**一个失效的把关机制比没有把关更危险** —— 因为它把"未知"转成了"已验证"。
`sflowse` 2026-08-15 一天内抓到**四个**同类:

| 机制 | 失效方式 | 输出的假信号 |
|---|---|---|
| `check_numbers.py` | 目标清单里 3 个文件早已不存在,静默 skip | **">>> 全部通过"** |
| `sha256_self` | 把哈希写进文件自身 → 写入即改变文件 | 一个**永远对不上**的 sha |
| `make_tables.py`(一) | `sorted(glob)[-1]` 按字母序选源 | 静默选中**诊断文件**当权威 |
| `make_tables.py`(二) | 回退时打了 `[WARN]`,**然后照样把数印出来** | 已作废的旧值进表 |

**规则**
1. **fail-closed**:把关机制的默认动作是**拒绝/空值**,不是放行。
   打了告警仍输出数字 = 没把关。**告警不是把关,拦截才是。**
2. **自失败测试**:每个把关脚本必须有一条**已知会失败**的输入,并断言它确实失败。
   目标文件不存在 → **非零退出**,不是 skip 后报通过。
3. **不可自指**:校验值不得存放在被校验对象内部(旁挂 `.sha256`,不是 `sha256_self`)。
4. **选源不许靠排序/通配**:显式写死"哪个量取自哪个文件的哪个字段";
   维护一份**作废源清单**,命中即硬拦并说明理由。
5. **输入充分性自检(M27.2 补,导师1 漏项)**:工具**对退化输入照样出结论**,是同一族的失效。
   血泪:漂移汇总把一个 **n=3** 的尾窗当完整窗,算出 +4.53% 并在 json 里写下
   **"热降频迹象"** —— 而 3 条样本的 SE 就有 ±5.0%,那是采样噪声被写成了物理现象。
   → 每个聚合/判定函数必须**先检查样本量与代表性**(n 下限、窗完整度、分布覆盖),
     不足即返回 `INSUFFICIENT` 并**拒绝出结论**,不得输出一个看起来正常的数。
   → 凡输出"趋势/迹象/机制"字样的字段,**必须同时输出其 n 与不确定度**。

## 铁律 15:任何对比,先对齐**入口条件**并落盘;查错先查边界,不查中间

`sflowse` 同日绕了三圈,**中间逻辑一次都没错,错全在边界**:
跨口径(冷子集 vs 热全语料)· 混环境(污染日基线 vs 净化后数据)· 漏预处理(复用管线时手写入口漏 48k→16k 重采样)。
每次都在中间逻辑里找了很久。

**规则**
1. **对比前先写下双方共享什么、不共享什么**:语料/样本量、环境与后台负载、预处理与采样率、
   冷热态、软件路径与算子后端、测量协议。**不共享的那些就是嫌疑犯名单。**
2. **入口条件写进产物本身**(环境快照、op_path、语料 n、预处理链),
   而不是靠事后考古 —— 我们为此考古了一整天。
3. **"多个测量互相吻合"不自动构成独立佐证。**(M27.3 修订:原写"只有排除共同混杂后才算",字面过强)
   **独立性是相对于待证命题而言的。判据 = 它们共享的因素,能否单独解释这次吻合?**
   - 能 → 那只是同一个错误的多个副本(如:换脚本换协议但**共享污染环境**,四个测量一致却全错);
   - 不能 → 吻合是**强证据**,哪怕它们共享很多东西。
   ⚠️ **反例就在同一天**:15W 在**干净环境**下冷子集与热全语料只差 −0.1%,
   而 25W 同一对差 12.7% —— **跨环境的吻合/不吻合本身成了判定污染的强证据**。
   所以不要机械地"共享 = 不独立",要问"共享的那部分能不能解释你看到的这个吻合"。
4. **复用管线先 `diff` 入口函数**(load/预处理/归一化)。手写的 loader 是最高发的错误源。
5. **排查顺序**:先边界(输入、环境、口径),后中间(算法、公式)。反过来是浪费。

### 铁律 15 附则:配对必须按**标识符**对齐,不按行号
> **接缝(M27.1)**:本附则同时是**铁律 14 在"配对"场景下的实例** —— 按行号配对是 fail-open
> (顺序错了也照样出数),按标识符配对并断言一致才是 fail-closed(对不上就拒绝出数)。
> 两条铁律在此处交汇:**14 管"守卫怎么写",15 管"比较双方是否可比"。**
`n` 相等只证明**集合**相同,证明不了**顺序**相同。任何逐样本配对(配对 t / TOST / Δ)
**必须按文件名(或唯一 id)对齐并断言两侧完全一致**,不得依赖行号。
→ 逐样本产物**一律带 id 列**;没有 id 列的历史产物只能作 sanity 锚,不得进配对分析。
血泪:`sflowse` 曾产出无文件名列的逐句 CSV,只能靠 `corr=0.947` vs 错位一格 `corr=0.144` 反推行序 ——
那是运气,不是方法。

### 铁律 14 执行细则:撤回必须 grep 全仓扫引用
**只改源头不扫引用 = 没撤。** 撤回/作废是一个**拦截动作**,它同样必须 fail-closed:
被撤回的结论若仍在别处被当作依据引用,它就没有被撤回。
→ 任何"作废某数/撤回某结论"之后,**立刻全仓 grep 该数值与该结论的措辞**,逐处标注或改写。
→ **扫描必须覆盖结论的全部数值别名,不是只扫"最新的那个数"**:一个量被多次重设后
  (如锚 2.50 → 2254 → 新值),每一代数值都是同一撤回链的引用面;只扫当前值会漏掉
  所有还挂着上一代数值的文件(sflowse 血泪:撤"能耗律成立"只 grep 了新锚 2095,
  三代旧锚 2.50/2494/2254 在 4 个文件里裸挂到第三轮扫描才清)。
→ 撤回三步闭环:**原地标注 + 全仓 grep(按别名族)+ 登记扫描结果**(扫了什么词、命中几处、状态)。
→ ⚠️ **扫描器本身要防 fail-open**:用词边界(否则 `12.7` 会命中 `14212.7`);
   作废标记若挂在**段标题**上,行级扫描会漏 —— 需按**段落作用域**判定,或要求标记与数值同行。
血泪:`sflowse` 正式撤回"计票 5:1"并写了整节说明,但该结论已渗进另一文件的**标题行**继续充当依据;
两轮扫描(导师 3 处 + student 6 处)之后,第三轮仍在资产表与分档表里各找到 1 处裸引。
